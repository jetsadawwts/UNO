# หน้า Office (ทางเลือก A) — ร่างแบบ รออนุมัติ

## เป้าหมาย
เจ้าของเปิดหน้าเดียวแล้วเห็นว่า พนักงานแต่ละคนทำอะไร ใครส่งงานอะไรให้ใคร task ถึงขั้นไหน และติดอะไร

## ไม่ทำ
- ไม่เก็บคำสั่งงานฉบับเต็ม (prompt), คำตอบของ agent, คำสั่ง shell, path หรือเนื้อหาไฟล์
- หน้าเว็บอ่านอย่างเดียว สั่งงานหรืออนุมัติจากหน้าไม่ได้
- ไม่ให้ agent คุยกันเองหรือทำงานเอง
- ไม่แสดงสถานะหรือขั้นที่เดาเอา ถ้าไม่มีบันทึกให้เว้นว่าง

## ทางเลือกที่พิจารณา
| ทาง | ได้ | เสีย |
|---|---|---|
| **A (เลือกเป็นฐานข้อมูล)** หน้า Office จากข้อมูลการทำงาน | รายคน การส่งงาน ขั้นของ task และจุดที่ติด | ไม่รู้ว่า agent ตอบอะไร |
| B: A + เก็บผลตอบกลับแบบย่อ | เห็นขาไปและขากลับ | เนื้อหาจากงานอาจถูกเก็บและขึ้นจอ |
| C: A แบบมีตัวละครและโต๊ะ | เห็นภาพสนุกกว่า | งานวาดและดูแลเพิ่ม ข้อมูลเท่า A |

เจ้าของเลือก A แล้วขอเพิ่มภาพแบบ C บางส่วน: agent ที่ว่างแอบไปห้องน้ำหรือลุกจากโต๊ะ ข้อมูลยังเท่า A

## ฉากออฟฟิศ (อยู่ในช่วงที่ 1)
มีโต๊ะ 12 ตัว และมุมพัก 3 จุด: ห้องน้ำ, ห้องกาแฟ, โซฟา

| สัญญาณจริง | ภาพ | ป้ายใต้ตัวละคร |
|---|---|---|
| กำลังรัน tool หรือกำลังทำงาน | นั่งโต๊ะ พิมพ์งาน | งานที่ทำ + เลข task |
| รอคุณตอบ | อยู่ที่โต๊ะ ยกมือ | รอคุณตอบ |
| หยุดเพราะ error | อยู่ที่โต๊ะ มีเครื่องหมายเตือน | error |
| ตอบรอบนั้นเสร็จ | นั่งพักที่โต๊ะ | ตอบรอบนั้นเสร็จ |
| ไม่มีสัญญาณ | ลุกจากโต๊ะ ไปมุมพัก | ว่าง |

- มุมพักที่ไปเป็นของตกแต่ง สุ่มสลับทุก 2–3 นาที **ไม่ได้มาจากข้อมูลจริง** ป้ายต้องเขียน "ว่าง" เสมอ และมีข้อความบอกบนหน้า
- "ว่าง" หมายถึงไม่มีสัญญาณจาก hook
- มีสัญญาณใหม่ ตัวละครเดินกลับโต๊ะ สถานะและป้ายเปลี่ยนทันทีโดยไม่รอการเดิน
- ตัวละครวาดเองด้วย SVG/CSS ไม่ใช้ภาพหรือไลบรารีจากภายนอก
- ถ้าเครื่องตั้งให้ลดการเคลื่อนไหว ให้ย้ายตำแหน่งโดยไม่มีแอนิเมชัน

## ช่วงที่ 0: ทดสอบสัญญาณใน Cowork (ยังไม่แก้ UNO)
ใส่ hook ทดสอบชั่วคราวใน `.claude/settings.local.json` ของโปรเจกต์ทดสอบ สำรองก่อน และถอดเมื่อเสร็จ
บันทึกเฉพาะชื่อเหตุการณ์ ชื่อ field, id, ชนิด agent และเวลา ต้องตอบให้ได้ว่า:
1. `SubagentStart` / `SubagentStop` มาหรือไม่
2. เหตุการณ์ tool ภายใน subagent มี `agent_id` หรือไม่
3. `PostToolUse` ของ Agent มี `agentId` ให้จับคู่กับคำอธิบายงานหรือไม่ ทั้งแบบรอผลและแบบเบื้องหลัง

เอกสาร Claude Code ระบุว่ามีทั้งสามอย่าง แต่ยังไม่ได้ยืนยันใน Cowork
**ถ้าข้อ 1 หรือ 2 ไม่มา ให้หยุดและเสนอแบบใหม่** ถ้าขาดเฉพาะข้อ 3 ช่วงที่ 2 จะต้องปรับก่อนทำ

## ช่วงที่ 1: รายคน (v0.5.22)
- heartbeat แยกไฟล์: งานหลัก (Uno) ใช้ `<session>.json` เหมือนเดิม, subagent ใช้ `<session>.<agent_id>.json`
- `SubagentStart` สร้างไฟล์ของคนนั้น, `SubagentStop` ลบ, `SessionEnd` ลบทุกไฟล์ของ session
- จำนวน session นับไม่ซ้ำเหมือนเดิม แม้มีหลายไฟล์
- การ์ดบน dashboard เดิมจะแสดงบรรทัดแยกตามคนด้วย (จากเดิม session ละบรรทัด)
- hook ใหม่ไม่พิมพ์ข้อความ จบด้วยรหัส 0 เสมอ ไม่บล็อกและไม่เติม context ให้ agent
- `SubagentStop` ของ agent ภายในที่ไม่เคยมีไฟล์เริ่ม ให้ข้ามไป
- เพิ่มแท็บ **ออฟฟิศ / Office** เป็นฉากออฟฟิศของทีม 12 คนตามหัวข้อข้างบน มีรายการตัวหนังสือประกอบ
- คนเดียวกันทำพร้อมกันหลายตัว แสดงหลายบรรทัด agent นอกทีมรวมในกลุ่ม "ตัวช่วยอื่น"
- บรรทัดที่ไม่มีสัญญาณเกิน 30 นาทีถูกซ่อน เหมือนการ์ดปัจจุบัน

## ช่วงที่ 2: ลำดับการส่งงาน (v0.5.23)
- ไฟล์ใหม่ `.uno/office.log` บันทึก เวลา, session, agent_id, ชนิด agent, เริ่ม/จบ และคำอธิบายงานไม่เกิน 120 ตัวอักษร
  (คำอธิบายแบบนี้มีใน `audit.log` อยู่แล้ว) ไม่ปนกับ `audit.log` ตัวเลขเดิมจึงไม่เปลี่ยน
- จาก `PostToolUse` ของ Agent อ่านเฉพาะ `agentId`, `status` และ `description` **ไม่อ่านค่า `prompt` หรือ `content` ไปเก็บ**
- งานแบบรอผลอาจได้ `agentId` ตอนจบ ระหว่างทำจะใส่คำอธิบายเฉพาะเมื่อมีงานชนิดเดียวกันค้างอยู่รายการเดียว
  ไม่เช่นนั้นเว้นว่างจนจับคู่ได้แน่นอน
- `status = async_launched` หมายถึงเริ่มงานเบื้องหลัง ไม่ใช่จบ เวลาจบใช้ `SubagentStop`
- หน้า Office แสดง 20 รายการล่าสุด: เวลาเริ่ม, Uno → ใคร, งานอะไร, เวลาจบหรือ "ยังทำอยู่"
  ถ้า session จบหรือเงียบเกิน 30 นาทีโดยไม่มีเวลาจบ ขึ้น "ไม่ทราบผล"
- เมื่อไฟล์เกิน 1 MB เก็บ 1,000 บรรทัดล่าสุด

## ช่วงที่ 3: ขั้นของงานและจุดที่ติด (v0.5.24)
- ขั้นของงานใช้เฉพาะ status ใน `tasks.md` (ready → in-progress → in-review → done) และเครื่องหมาย "อนุมัติแผนแล้ว" จาก `audit.log`
- แสดง task ที่ ready, in-progress, in-review, escalated และ task ที่มี session สดอยู่
- รายการ "ต้องดู" เรียงตามนี้:

| รายการ | มาจาก | หายเมื่อ |
|---|---|---|
| รอคุณตอบ / หยุดเพราะ error | สถานะสด | สถานะเปลี่ยน หรือเกิน 30 นาที |
| escalated | `tasks.md` | status เปลี่ยน |
| รอ review | `tasks.md` (in-review) | status เปลี่ยน |
| เพิ่งถูกบล็อก / เพิ่งมีการขอยืนยัน | `audit.log` ภายใน 30 นาที | ครบ 30 นาที (ไม่ได้แปลว่ายังติดอยู่ หน้าเว็บต้องเขียนตามนี้) |

- ไม่แสดงคอลัมน์หมายเหตุของ `tasks.md`

## หน้าจอ (บนลงล่าง)
ตัวเลือกโครงการ → ต้องดู → ขั้นของงาน → ทีม → การส่งงาน อัปเดตสดผ่านช่องทางเดิม รองรับไทย/อังกฤษ และธีมเดิม
แท็บแสดงส่วนที่มีข้อมูลแล้วตามช่วงที่ทำเสร็จ

## ข้อจำกัด
- ขึ้นกับ hook: การกดหยุดกลางทางหรือ tool ที่ถูกบล็อกอาจทำให้สถานะค้าง
- การแจ้งเตือนที่ไม่มี `agent_id` จะนับเป็นของ Uno
- `tasks.md` อัปเดตโดย skill ถ้าไม่ได้อัปเดต ขั้นบนหน้าจะช้ากว่างานจริง
- ไม่มีขั้นย่อยระหว่าง in-progress
- คำอธิบายงานและชื่อ task อาจมีข้อมูลบริษัท หน้านี้ห้ามแชร์ เหมือน dashboard เดิม

## การตรวจ การออกรุ่น และ rollback
- แต่ละช่วง: เสนอแผนและรออนุมัติ → เขียนเทสต์ก่อน → รันเทสต์ทั้งหมด → เปิดหน้าเว็บจริง → ลองกับ session จริง
- ทดสอบว่าไฟล์ที่ hook เขียนไม่มี prompt, คำตอบ, คำสั่ง หรือ path
- อัปเดต CHANGELOG, ARCHITECTURE, SECURITY, ONBOARDING และคู่มือ (สำรองก่อน) พร้อมเลขรุ่นทั้งสองไฟล์
- commit เมื่อเจ้าของสั่ง แยกรุ่นละ commit และเจ้าของ push เอง
- rollback: ก่อน commit คืนไฟล์, หลัง push ใช้ `git revert` แล้วอัปเดต plugin และ `uno-report`
